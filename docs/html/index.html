DataShare

Partage de fichiers par lien, avec expiration, tags et mot de passe optionnel. Projet du cours "Pilotez le développement d'une application full-stack complète" de la formation Architecte Logiciel d'OpenClassrooms.

API Symfony 8 et API Platform, front React 19 et Vite, PostgreSQL, stockage S3. Tout tourne dans Docker.

Prérequis

Docker et Docker Compose. Rien d'autre à installer, ni PHP, ni Node, ni PostgreSQL.

Démarrer

cd DataShare_API
make init              # dependances PHP, cles JWT, base de donnees migree
cd ..
docker compose up -d   # demarre l'API et le front ensemble

Le front installe ses dépendances npm à son premier démarrage, comptez une minute avant qu'il réponde.

Quoi Adresse
Application http://localhost:5173
API, documentation interactive comprise http://localhost:8080/api
Base de données (Adminer) http://localhost:8081
Stockage S3, l'API http://localhost:8333
Stockage S3, le contenu du bucket http://localhost:8888/buckets/datashare/

Pour Adminer : système PostgreSQL, serveur database (pré-rempli), puis utilisateur, mot de passe et base depuis DataShare_API/.env, soit app / !ChangeMe! / app par défaut.

Le port 8333 est l'API S3, celle que l'application appelle : ouvert dans un navigateur, il ne montre rien d'utile. Pour voir les fichiers envoyés, c'est le port 8888, l'interface du filer de SeaweedFS. Elle liste, télécharge et supprime, rien de plus. Les deux ports n'écoutent que sur votre machine, le stockage ne demandant aucun mot de passe en local.

Ensuite, docker compose up -d et docker compose down depuis la racine suffisent au quotidien.

Configuration

Les valeurs par défaut sont versionnées et suffisent à travailler en local. Elles sont dans DataShare_API/.env et DataShare_Front/.env.

Ce qui vous est propre va dans un fichier .env.local à côté, jamais commité :

Variable Fichier À quoi elle sert
JWT_PASSPHRASE DataShare_API/.env.local protège les clés JWT, créée par make init
VITE_API_URL DataShare_Front/.env.local adresse de l'API appelée par le navigateur

Bon à savoir

  • node_modules vit dans un volume Docker, pas sur votre disque. Un npm install lancé sur le poste ne sert qu'à votre éditeur.
  • Ne lancez pas le front seul et la stack racine en même temps. Les deux publient le port 5173. Soit docker compose up -d depuis la racine, soit make up dans chaque dossier, pas les deux.
  • Les migrations sont la source unique du schéma. doctrine:schema:update n'est pas utilisé ici.
  • Les tests ne touchent pas votre base de développement, ils ont la leur.
  • Les tests de bout en bout ne fonctionnent que sous Linux, le conteneur Cypress utilisant le réseau de l'hôte.
